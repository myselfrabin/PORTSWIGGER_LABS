🔐 Professional CSRF Exploitation Roadmap

This roadmap is designed for web hackers and bug bounty hunters to identify and exploit CSRF (Cross-Site Request Forgery) vulnerabilities effectively.

✅ 1. Recon and Target Identification

  • Look for state-changing requests like POST to /change-email, /delete-account, etc.
  • Use Burp Suite to intercept and analyze requests triggered from the UI.
  • Focus on authenticated actions requiring user login.

🔍 2. Check for CSRF Protection Mechanisms

  • Look for CSRF tokens (e.g., csrf, token) or custom headers.
  • Inspect if cookies have SameSite attributes: Lax, Strict, or None.
  • If a token is missing or predictable → high chance of vulnerability.

🔄 3. Generate a CSRF Proof of Concept (PoC)

Use Burp Suite’s CSRF PoC generator or create one manually:

<html>
  <body>
    <form action="https://target.site.com/path/to/change" method="POST">
      <input type="hidden" name="param" value="malicious_value" />
      <input type="hidden" name="csrf" value="hardcoded_or_missing_token" />
      <input type="submit" value="Submit request" />
    </form>
    <script>
      history.pushState('', '', '/');
      document.forms[0].submit();
    </script>
  </body>
</html>
  • Host on a different origin (e.g., attacker.com).
  • Deliver via phishing, email, embedded iframe, etc.

🧪 4. Test the CSRF PoC

  • Log in as victim in one browser.
  • Open your PoC page in another tab or iframe.
  • If the state change succeeds silently → valid CSRF.

🛠️ 5. Bypass Techniques (If Token Present)

  • Check for static or reusable tokens.
  • Tokens not rotated or validated.
  • Misconfigured SameSite attributes.
  • Predictable token values.

🪓 6. Impact Demonstration

  • Show how CSRF can lead to email change, password reset, or account deletion.
  • Provide clear proof: screenshots or demo video.

📝 7. Reporting

  • Title: CSRF on Change Email → Account Takeover
  • URL: https://example.com/my-account/change-email
  • PoC: Include HTML + steps
  • Impact: Exploits authenticated trust and changes sensitive data.
  • Fix:
    • Implement anti-CSRF tokens (random per request).
    • Use SameSite=Strict or Lax.
    • Check Origin or Referer headers.

🧠 Bonus Tips

  • Check for GET-based CSRF (less common, more dangerous).
  • Focus on mobile apps or outdated admin panels.
  • Use Burp extensions like CSRF Scanner.
  • Chain CSRF with IDOR or XSS for greater impact.

Stay curious, stay ethical — and happy hacking! ⚔️🧠
