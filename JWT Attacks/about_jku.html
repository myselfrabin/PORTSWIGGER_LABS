What does the jku do in a JSON Web Token (JWT)?

1️⃣ Layman’s Explanation

Imagine you get a signed letter — it says it’s from your bank. You want to make sure it’s really from your bank, not from a scammer. So you check the signature — but how do you know what your bank’s signature looks like?

The jku in a JWT is like a note in the letter that says:

“Hey! If you want to verify my signature, go to this website — there you’ll find my real signature to check with.”

So:

  • The JWT is the letter.
  • The jku is a URL inside the JWT that tells you where to fetch the public key that was used to sign the JWT.
  • If you trust the URL, you trust the key, so you can verify the signature.

In simple words: ✅ jku = “Here’s where to get the key to check if I’m real.”

2️⃣ Student-level (Cybersecurity / Developer)

In JWT (JSON Web Token), the jku (JSON Key URL) is a header parameter that tells the recipient where to find the JSON Web Key Set (JWKS) that contains the public key(s) to verify the token’s signature.

How it works:

  • JWTs are signed with a private key.
  • To verify it, you need the matching public key.
  • Instead of hard-coding keys, the JWT can include jku: "https://example.com/keys.json".
  • The server verifying the JWT fetches the JWKS from that URL.
  • The JWKS is a JSON file that lists one or more public keys.
  • The server picks the right key (often based on the kid header) and verifies the signature.

🔒 Security Risk:

If an attacker can tamper with jku, they could point it to their own server with their own key — making fake tokens appear valid. So:

  • You must only trust jku values from trusted issuers.
  • Many systems disable jku entirely or only allow it if the issuer is verified.

✅ Summary

  • Layman: Tells you where to get the real signature to check.
  • Student: A URL pointing to a trusted JWKS that holds the public key to validate the JWT signature.
