Stored XSS in onclick Event - Methodology

Lab Situation:

  • Context: Stored XSS vulnerability inside an onclick JavaScript event.
  • Filters:
    • Angle brackets (<, >) and double quotes (") are HTML-encoded.
    • Single quotes (') and backslashes (\) are escaped.
  • Task: Inject a payload that triggers alert(1) when the comment author's name is clicked.

Analysis Methodology

1. Identify where your input lands

Post a comment and inspect the HTML and JavaScript generated. Find where your comment or author name is injected.

In this case:

onclick="var tracker={track(){}};tracker.track('https://www.google.com');"

2. Understand the JavaScript Context

Injection point is inside single quotes ('...') of a JavaScript function parameter.

Meaning your payload is inserted inside:

tracker.track('YOUR_INPUT_HERE');

3. Understand the Escaping/Encoding Behavior

  • Single quotes ' are escaped: \'
  • Backslashes \ are escaped.
  • Angle brackets < > and double quotes " are HTML-encoded.

✅ Observation: &apos; (') can be used to represent a single quote if HTML encoding is parsed before JavaScript execution.

4. Plan How to Break Out of Context

Goal: Break out of the '...' JavaScript string safely. Close the current string with ' (or &apos;), inject JavaScript (e.g., alert(1)), and prevent syntax errors.

Example Attack Plan:

https://www.google.com&apos;-alert(1)-&apos;

Which results in:

tracker.track('https://www.google.com'-alert(1)-'');

✅ This is valid JavaScript.
✅ The alert(1) gets executed.

Why use -?

  • - (minus) operators are neutral and keep JavaScript valid between expressions.
  • Without -, you could cause syntax errors.

5. Execute and Validate

  • Submit the payload in the comment author name.
  • Click the author name to trigger the onclick event.
  • Popup appears ✅.

Final General Methodology for Similar Situations

  1. Find out where your input is reflected.
  2. Understand the surrounding context (HTML? Attribute? JavaScript inside quotes?).
  3. Check escaping/encoding:
    • Are quotes (', ") escaped?
    • Are angle brackets (<, >) encoded?
    • Are backslashes (\) escaped?
  4. Choose a strategy to break out:
    • If inside a single quote: use &apos; if supported.
    • Close the quote, inject your payload (e.g., alert(1)), and close cleanly.
  5. Use neutral JavaScript operators like - to avoid breaking the syntax.
  6. Test your payload carefully in the developer console.
  7. Refine your payload if needed to adapt to extra filtering.
